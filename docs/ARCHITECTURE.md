# 架构说明

`content.ts` 检测前台游戏页、完整回合和生成结束状态；`background.ts` 管理请求去重、缓存、取消和播放租期；`offscreen.ts` 负责音频及交叉淡入淡出；`options.ts` 和 `popup.ts` 提供配置与控制界面。

配置按 Connection → ModelProfile → TaskBindings 分层。`profiles.ts` 负责升级、验证和任务解析，`providers.ts` 映射请求与响应，`core.ts` 将统一 Decision 用于本地音乐匹配。显示名称和家族建议不替代实际模型 ID 或能力配置。

自动回合请求使用指定的一个后端，失败不自动重试或切换；手动重判、模型测试和说明转标签是独立的显式请求。音乐列表不进入剧情分类请求，增减曲目不增加分类输入。签名不含服务密钥。

`db.ts` 与 `library-io.ts` 管理曲库、缓存、备份和可恢复操作。分类先过滤情绪及排除条件，再比较标签、强度和近期播放情况；当前曲目仍合适时保持播放。

真实模型服务及网站 DOM 属于外部依赖。自动测试使用隔离的模拟服务和数据库，不读取用户的浏览器配置、游戏或音乐。
